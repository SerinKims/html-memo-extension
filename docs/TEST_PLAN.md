# 테스트 계획

## 테스트 목표

- 연구원이 웹페이지에서 세 가지 유형의 메모를 작성할 수 있는지 검증한다.
- 메모가 `chrome.storage.local`에 안정적으로 저장되는지 검증한다.
- 전체 페이지 스크린샷과 메모가 단일 HTML 파일에 포함되는지 검증한다.
- 내보낸 HTML이 확장 프로그램과 네트워크 없이 `file://`에서 동작하는지 검증한다.
- 민감정보 제거 정책이 의도대로 적용되는지 검증한다.
- 저장소 사용량 경고와 정리 정책이 의도대로 동작하는지 검증한다.

## 단위 테스트

대상:

- 데이터 모델 검증 함수
- URL 정규화 함수
- 파일명 sanitize 함수
- 메모 좌표 변환 함수
- 비율 좌표 계산 함수
- 민감정보 마스킹 함수
- HTML JSON 이스케이프 함수
- 저장소 사용량 수준 계산 함수
- 정리 대상 우선순위 계산 함수

주요 케이스:

- 빈 메모 본문
- 매우 긴 메모 본문
- HTML 태그와 스크립트 문자열이 포함된 메모
- query parameter가 많은 URL
- 한글, 공백, 특수문자가 포함된 파일명
- 0 크기 또는 비정상 좌표

## 컴포넌트 테스트

대상:

- Popup 메모 목록
- 메모 작성 모드 선택
- 내보내기 설정 UI
- 민감정보 제거 확인 UI
- Content Script 오버레이 컴포넌트

검증 항목:

- 메모 유형별 아이콘과 상태가 올바르게 표시된다.
- 수정과 삭제 동작이 저장소에 반영된다.
- 캡처 진행 중 UI가 중복 실행을 막는다.
- 저장소 사용량 경고와 정리 버튼이 기준에 맞게 표시된다.
- 오류 메시지가 사용자가 이해할 수 있게 표시된다.

## 통합 테스트

대상 흐름:

1. 테스트 페이지 열기
2. 위치 메모 작성
3. 텍스트 메모 작성
4. 영역 메모 작성
5. Popup에서 메모 목록 확인
6. HTML 내보내기 실행
7. 다운로드된 HTML 열기
8. 메모 위치와 상세 내용 확인

검증 항목:

- 저장된 메모 수가 일치한다.
- 메모 유형이 유지된다.
- 스크린샷 크기와 문서 크기 메타데이터가 일치한다.
- Base64 이미지가 HTML 내부에 포함된다.
- JSON 데이터가 HTML 내부에 포함된다.
- 외부 네트워크 요청이 발생하지 않는다.

## 전체 페이지 스크린샷 테스트

테스트 페이지 유형:

- 짧은 정적 페이지
- 긴 문서형 페이지
- sticky header가 있는 페이지
- lazy loading 이미지가 있는 페이지
- iframe이 포함된 페이지
- 고해상도 화면에서 열린 페이지
- 스크롤 가능한 내부 컨테이너가 있는 페이지

검증 항목:

- 상단부터 하단까지 누락 없이 캡처된다.
- 뷰포트 경계가 어긋나지 않는다.
- 메모 좌표가 합성 이미지 위에서 일치한다.
- 너무 큰 페이지에서 사용자에게 명확한 오류 또는 축소 옵션을 제공한다.

## 내보낸 HTML 테스트

검증 절차:

1. 네트워크를 끈 상태에서 HTML 파일을 연다.
2. `file://` 경로로 직접 연다.
3. Chrome 확장 프로그램을 비활성화한 상태에서 연다.
4. 메모 목록, 필터, 상세 보기, 스크롤 이동을 확인한다.
5. 개발자 도구 Network 패널에서 외부 요청이 없는지 확인한다.

합격 기준:

- 외부 리소스 요청이 없다.
- 스크린샷이 표시된다.
- 메모 레이어가 스크린샷 위치와 맞는다.
- 메모 본문이 HTML로 실행되지 않는다.
- 민감정보 제거 요약이 표시된다.

## 보안 테스트

테스트 케이스:

- 메모 본문에 `<script>alert(1)</script>` 입력
- 메모 본문에 이미지 태그와 이벤트 핸들러 입력
- URL에 token, session, email query 입력
- 선택 텍스트에 개인정보 패턴 입력
- JSON 안에 `</script>` 문자열 입력

합격 기준:

- 스크립트가 실행되지 않는다.
- 사용자 입력은 텍스트로 표시된다.
- 민감 query parameter가 제거 또는 마스킹된다.
- JSON 파싱이 깨지지 않는다.

## 로컬 HTML 테스트

테스트 케이스:

- 파일 URL 접근을 끈 상태에서 Popup 실행
- 접근을 켠 뒤 한글, 공백, 특수문자가 포함된 경로의 HTML에서 메모 생성 및 재열기
- 같은 파일의 query 또는 fragment만 바꿔 재열기
- 파일 이동 또는 이름 변경 후 재열기
- PDF 등 `text/html`이 아닌 로컬 문서에서 실행
- 자체 내보낸 검토 HTML에서 Popup 실행

합격 기준:

- 권한이 꺼져 있으면 설정 이동 안내를 표시하고 주입하지 않는다.
- 같은 정규화 파일 URL의 메모는 복원되고 이동한 파일은 별도 페이지로 취급한다.
- HTML이 아닌 문서는 명확한 오류를 표시한다.
- 자체 검토 HTML에는 확장 오버레이가 중복 표시되지 않는다.
- 내보낸 데이터에는 로컬 절대 경로가 포함되지 않는다.

## 저장소 용량 테스트

테스트 케이스:

- 저장소 사용량이 8MB 미만인 상태
- 저장소 사용량이 8MB 이상인 상태
- 저장소 사용량이 9MB 이상인 상태
- 저장소 사용량이 9.5MB 이상인 상태
- 임시 작업 데이터가 많이 쌓인 상태
- 내보내기 이력이 30개를 초과한 상태
- 메모가 0개인 오래된 페이지 기록이 있는 상태
- 사용자 메모가 포함된 오래된 페이지가 있는 상태

합격 기준:

- 8MB 이상에서 경고가 표시된다.
- 9MB 이상에서 정리 권장이 표시된다.
- 9.5MB 이상에서 임시 데이터와 내보내기 이력이 우선 정리된다.
- 스크린샷 Base64와 생성된 HTML 본문이 `chrome.storage.local`에 남지 않는다.
- 사용자 메모 본문은 확인 없이 자동 삭제되지 않는다.
- `QuotaExceeded` 실패가 발생해도 사용자가 백업 또는 정리를 선택할 수 있다.

## 수동 인수 테스트

연구원 관점 체크리스트:

- 웹페이지 위에서 메모 작성 모드가 명확하다.
- 세 가지 메모 유형을 구분할 수 있다.
- 내보내기 전 어떤 정보가 포함되는지 알 수 있다.
- 민감정보 제거 옵션을 이해할 수 있다.
- 생성된 HTML 파일을 동료에게 전달할 수 있다.

검토자 관점 체크리스트:

- 확장 프로그램 없이 파일을 열 수 있다.
- 원본 URL과 캡처 시각을 확인할 수 있다.
- 메모 위치와 내용을 쉽게 찾을 수 있다.
- 메모 유형별로 검토할 수 있다.

## 회귀 테스트

릴리스 전 다음 항목을 반복 확인한다.

- 기존 저장 데이터 마이그레이션
- 이전 버전에서 만든 메모 표시
- 새 버전 ZIP 설치 후 데이터 유지
- 내보낸 HTML의 스키마 버전 호환성
- 권한 변경 여부
- 저장소 정리 정책 적용 후 메모 데이터 보존 여부
