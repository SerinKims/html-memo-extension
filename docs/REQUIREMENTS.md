# 요구사항

## 프로젝트 목표

연구원이 웹사이트 조사 중 발견한 내용에 대해 위치, 텍스트, 영역 단위로 메모를 작성하고, 해당 웹페이지 전체 스크린샷과 메모를 하나의 HTML 검토 파일로 저장할 수 있는 Chrome 확장 프로그램을 만든다.

생성된 HTML 파일은 독립 실행형 검토 파일이어야 한다. 파일을 받은 사람은 확장 프로그램, 서버, 인터넷 연결 없이도 브라우저에서 메모를 확인할 수 있어야 한다.

## 비목표

- 서버 또는 클라우드 저장소 구축
- 사용자 계정, 로그인, 조직 권한 관리
- 실시간 공동 편집
- 메모 공유 웹사이트 제공
- 원본 웹페이지를 HTML 파일 안에서 재현하거나 다시 실행
- 외부 CDN, 외부 JavaScript, 외부 CSS에 의존하는 검토 파일 생성
- Chrome 외 브라우저의 완전한 호환성 보장
- 내보낸 HTML 원본 파일의 자동 덮어쓰기 또는 여러 수정본의 자동 병합

## 대상 사용자

- 1차 사용자: 웹사이트를 조사하며 근거, 오류, 참고 사항을 기록하는 연구원
- 2차 사용자: 연구원이 전달한 HTML 파일을 열어 검토하는 동료, 의사결정자, 운영 담당자

## 연구원 사용 흐름

1. 연구원이 조사 대상 웹페이지를 연다.
2. Popup에서 메모 작성 기능을 활성화한다.
3. Content Script가 현재 페이지 위에 메모 오버레이를 표시한다.
4. 연구원은 다음 중 하나의 방식으로 메모를 작성한다.
   - 특정 좌표를 클릭하여 위치 메모 작성
   - 텍스트를 선택하여 텍스트 메모 작성
   - 드래그로 사각형 영역을 지정하여 영역 메모 작성
5. 작성한 메모는 즉시 `chrome.storage.local`에 저장된다.
6. Popup에서 현재 페이지의 메모 목록을 확인하고 수정, 삭제, 내보내기를 수행한다.
7. 내보내기 시 전체 페이지 스크린샷을 생성한다.
8. 스크린샷, 메모 JSON, 검토용 HTML/CSS/JavaScript를 하나의 `.html` 파일에 포함한다.
9. 연구원은 생성된 HTML 파일을 파일로 전달한다.
10. 수신자는 HTML 파일을 열어 스크린샷 위의 메모 핀, 선택 텍스트, 영역 표시와 상세 내용을 확인한다.

## 로컬 HTML 사용 흐름

1. 연구원이 Chrome에서 임의의 로컬 HTML을 `file://`로 연다.
2. 확장 관리 화면에서 이 확장 프로그램의 `파일 URL에 대한 액세스 허용`을 켠다.
3. Popup에서 메모 작성을 시작하면 기존 Content Script 오버레이가 사용자 동작에 의해 주입된다.
4. 메모는 전체 로컬 경로로 페이지를 구분해 `chrome.storage.local`에 저장하지만, 내보낸 HTML에는 파일명만 포함한다.
5. 파일을 이동하거나 이름을 바꾸면 별도 페이지로 취급한다.

## 검토자 수정 흐름

1. 수신자는 내보낸 HTML을 확장 프로그램과 네트워크 없이 연다.
2. 스크린샷 위에 위치 또는 영역 메모를 추가하거나 좌표 없는 일반 댓글을 작성한다.
3. 기존 메모의 내용, 작성자, 색상, 해결 상태를 수정하거나 삭제할 수 있다.
4. 변경사항은 브라우저 메모리에만 유지되며 `수정본 다운로드`로 다음 revision의 단일 HTML을 저장한다.
5. 원본 파일은 덮어쓰지 않고 분기된 수정본의 자동 병합은 지원하지 않는다.

## 메모 유형

### 위치 메모

- 페이지 내 특정 좌표에 작성하는 메모이다.
- 저장 좌표는 문서 기준 좌표와 스크린샷 기준 비율 좌표를 함께 보관한다.
- 스크롤 위치가 달라도 같은 위치를 복원할 수 있어야 한다.

### 텍스트 메모

- 연구원이 선택한 텍스트 범위에 작성하는 메모이다.
- 선택 텍스트, 주변 문맥, 가능한 경우 DOM 선택자 또는 텍스트 위치 정보를 저장한다.
- 내보낸 HTML에서는 원본 DOM을 재구성하지 않고 스크린샷 위에 하이라이트와 메모를 표시한다.

### 영역 메모

- 연구원이 드래그로 지정한 사각형 영역에 작성하는 메모이다.
- 문서 기준 좌표, 크기, 스크린샷 기준 비율 좌표를 저장한다.
- 내보낸 HTML에서는 스크린샷 위에 사각형 표시와 메모 내용을 렌더링한다.

## 기능 요구사항

- 현재 탭의 URL, 제목, 캡처 시각을 기록한다.
- 페이지별로 여러 개의 메모를 저장한다.
- 메모 생성, 수정, 삭제를 지원한다.
- 메모에는 본문, 유형, 작성 시각, 수정 시각, 작성 위치 정보를 포함한다.
- 내보내기 전 민감정보 제거 옵션을 제공한다.
- HTML 파일명은 페이지 제목과 내보내기 시각을 기반으로 생성한다.
- 내보낸 HTML은 확장 프로그램 API 없이 동작한다.
- 저장소 사용량을 사용자에게 표시하고, 제한에 가까워지면 정리 안내를 제공한다.
- 스크린샷 Base64와 생성된 HTML 파일은 `chrome.storage.local`에 장기 저장하지 않는다.
- 사용자 메모는 백업 또는 명시적 확인 없이 자동 삭제하지 않는다.
- 로컬 파일 URL은 내부 페이지 식별에만 전체 경로를 사용하고 내보내기 데이터에는 파일명만 남긴다.
- 내보낸 HTML은 위치, 영역, 일반 댓글의 오프라인 작성과 새 revision 다운로드를 지원한다.
- 자체 내보낸 HTML에는 확장 오버레이를 중복 주입하지 않는다.

## 비기능 요구사항

- 기본 저장소는 로컬 브라우저의 `chrome.storage.local`이다.
- `chrome.storage.local`의 기본 용량 제한은 약 10MB로 보고 설계한다.
- 저장소 사용량이 8MB를 넘으면 경고하고, 9MB를 넘으면 정리를 권장하며, 9.5MB 이상에서는 임시 데이터와 내보내기 이력을 우선 정리한다.
- 기본 동작에서 외부 네트워크 요청을 수행하지 않는다.
- 내보낸 HTML은 인터넷 연결이 없어도 열 수 있어야 한다.
- 긴 페이지에서도 실패 원인을 사용자에게 명확히 알려야 한다.
- 메모 데이터와 스크린샷이 큰 경우 브라우저 메모리 제한을 고려한다.

## 예상되는 기술적 제한

- `chrome://`, Chrome Web Store, 브라우저 내부 페이지 등에는 Content Script를 주입할 수 없다.
- `file://` 주입은 Manifest 권한과 별도로 사용자가 Chrome 확장 관리 화면에서 파일 URL 접근을 허용해야 한다.
- 로컬 HTML이 이동하거나 이름이 바뀌면 안정적인 파일 식별자가 없으므로 새 페이지로 취급한다.
- 일부 사이트의 보안 정책, 캔버스, 동영상, WebGL, 고정 요소는 스크린샷 결과가 원본 화면과 다를 수 있다.
- 매우 긴 페이지는 캡처와 이미지 합성 과정에서 메모리 제한에 걸릴 수 있다.
- 무한 스크롤 페이지는 실제 로드된 영역까지만 안정적으로 캡처할 수 있다.
- sticky/fixed 요소는 스크롤 캡처 중 반복 표시될 수 있어 보정 로직이 필요하다.
- cross-origin iframe 내용은 화면에는 캡처될 수 있지만 DOM 기반 텍스트 앵커는 제한될 수 있다.
- 내보낸 HTML은 정적 검토 파일이므로 원본 웹사이트의 인터랙션을 재현하지 않는다.

## 완료 기준

- 문서 간 용어, 데이터 흐름, 저장 방식이 일관된다.
- 구현자가 문서만 읽고 확장 프로그램의 구조를 이해할 수 있다.
- 서버 또는 클라우드 저장소를 전제로 한 설계가 없다.
- 내보내기 결과가 단일 HTML 파일이라는 원칙이 모든 문서에서 유지된다.
