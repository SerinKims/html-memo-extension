# 보안 및 개인정보 정책

## 기본 원칙

- 데이터는 로컬 브라우저에만 저장한다.
- 서버, 클라우드 저장소, 외부 API로 메모 또는 스크린샷을 전송하지 않는다.
- 내보낸 HTML은 독립 파일이며, 외부 리소스를 로드하지 않는다.
- 권한은 기능 구현에 필요한 최소 범위로 제한한다.
- 민감정보가 포함될 수 있는 화면 전체를 캡처하므로 내보내기 전 확인 절차를 둔다.

## 저장 위치

- 메모 데이터: `chrome.storage.local`
- 내보내기 파일: 사용자가 선택하거나 브라우저 다운로드 정책에 따른 로컬 파일
- 전체 페이지 스크린샷: 기본적으로 내보내기 작업 중 메모리에서만 유지

## 저장소 용량 정책

`chrome.storage.local`은 기본적으로 약 10MB 제한이 있으므로 저장소에는 장기 보존이 필요한 작은 데이터만 저장한다. 스크린샷 Base64, 생성된 HTML 본문, 캡처 조각 이미지는 저장소에 장기 보관하지 않는다.

정책은 다음과 같다.

- 사용량은 `chrome.storage.local.getBytesInUse(null)`로 측정한다.
- 8MB 이상이면 사용자에게 경고한다.
- 9MB 이상이면 정리 권장 상태로 표시한다.
- 9.5MB 이상이면 임시 데이터와 내보내기 이력을 우선 정리한다.
- 사용자 메모 본문은 백업 또는 명시적 확인 없이 자동 삭제하지 않는다.
- `unlimitedStorage` 권한은 기본 권한으로 요청하지 않는다.

## 민감정보 제거 정책

내보내기 전 다음 항목을 제거하거나 마스킹할 수 있어야 한다.

- URL의 민감한 query parameter
- access token, session id, auth code로 추정되는 문자열
- 이메일 주소
- 전화번호
- 주민등록번호 등 개인식별번호 패턴
- 신용카드 번호로 추정되는 숫자 패턴
- 사용자가 직접 지정한 금칙어 또는 마스킹 키워드
- 메모 작성자 이름 같은 선택적 작성자 메타데이터

기본 정책은 다음과 같다.

- URL query parameter는 기본적으로 제거하거나 사용자의 확인을 받는다.
- 메모 본문은 자동 마스킹 후보를 표시하고 사용자가 확인한다.
- 스크린샷 이미지 안의 텍스트는 자동 제거가 어렵기 때문에 내보내기 전 경고와 수동 확인을 제공한다.
- 민감정보 제거 적용 여부와 제거된 필드 종류는 `RedactionSummary`에 기록한다.

## 내보낸 HTML 보안

내보낸 HTML은 다음 조건을 만족해야 한다.

- 외부 스크립트를 로드하지 않는다.
- 외부 CSS를 로드하지 않는다.
- 외부 이미지나 폰트를 로드하지 않는다.
- 메모 본문은 HTML로 직접 삽입하지 않고 텍스트로 이스케이프한다.
- JSON 데이터는 `<script type="application/json">` 안에 넣고 안전하게 이스케이프한다.
- 인라인 JavaScript는 검토 UI 동작에 필요한 최소 코드만 포함한다.
- `file://`에서 열어도 네트워크 요청을 하지 않는다.

## 권한 최소화

권장 권한은 다음과 같다.

```json
{
  "permissions": [
    "activeTab",
    "storage",
    "downloads",
    "scripting",
    "offscreen"
  ],
  "host_permissions": ["file:///*"]
}
```

- `activeTab`: 사용자가 명시적으로 활성화한 탭에서 작업
- `storage`: 메모 로컬 저장
- `downloads`: 단일 HTML 파일 저장
- `scripting`: 필요한 경우 Content Script 주입
- `offscreen`: Canvas 이미지 합성
- `file:///*`: 사용자가 명시적으로 허용한 경우 임의의 로컬 HTML에 런타임 주입

`file:///*`는 특정 파일 하나가 아니라 Chrome이 접근 가능한 모든 로컬 파일 URL 범위다. 설치 및 Popup 안내에서 이 의미를 고지하고, 사용자가 메모 시작을 누르기 전에는 Content Script를 자동 주입하지 않는다. HTTP/HTTPS 전체 호스트 권한은 요청하지 않는다.

`unlimitedStorage` 권한은 기본 설계에 포함하지 않는다. 실제 연구 업무에서 10MB 제한을 자주 넘는다는 근거가 생길 때만 별도 의사결정으로 검토한다.

## 위협 모델

### 로컬 파일 유출

내보낸 HTML에는 스크린샷과 메모가 포함된다. 파일을 전달받은 사람은 파일 안의 모든 정보를 볼 수 있다. 따라서 내보내기 전 검토와 민감정보 제거 절차가 중요하다.

임의 로컬 HTML 메모를 구분하기 위한 절대 경로는 `chrome.storage.local` 내부에서만 사용한다. 내보내기 변환 시 annotation의 `originalUrl`, 드라이브명, 사용자명, 디렉터리 경로를 제거하고 `source.fileName`만 남긴다.

### 검토 HTML 수정본

검토 HTML의 새 메모는 브라우저 메모리에만 유지한다. 인라인 생성기는 원본 파일을 덮어쓰지 않고 새 Blob 다운로드만 수행하며, revision HTML에도 외부 URL이나 로컬 절대 경로를 새로 추가하지 않는다. 미저장 변경이 있으면 페이지 이탈 경고를 표시한다.

### 메모 본문 XSS

사용자가 입력한 메모에 HTML 또는 JavaScript가 포함될 수 있다. 내보낸 HTML 생성 시 모든 사용자 입력은 텍스트로 이스케이프하고, DOM 삽입 시 `textContent`를 사용한다.

### 원본 페이지 간섭

Content Script는 원본 페이지에 오버레이를 추가한다. 원본 페이지의 전역 상태를 오염시키지 않도록 Shadow DOM 또는 격리된 루트 노드를 사용한다.

### 외부 추적

외부 폰트, CDN, 분석 스크립트, 원격 이미지 로딩을 금지한다. 검토 파일을 열 때 외부 서버로 접속 흔적이 남지 않아야 한다.

## 감사 체크리스트

- 내보내기 HTML에 `http://` 또는 `https://` 리소스 참조가 없는가?
- 사용자 입력이 HTML로 직접 삽입되지 않는가?
- 캡처 이미지가 로컬 저장소에 불필요하게 장기 보관되지 않는가?
- 저장소 사용량 경고와 정리 정책이 동작하는가?
- 사용자 메모가 확인 없이 자동 삭제되지 않는가?
- 권한 요청이 기능 설명과 일치하는가?
- 민감정보 제거 적용 여부가 내보내기 전에 사용자에게 표시되는가?
